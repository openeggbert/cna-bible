\chapter{free-direct and free-api}
\label{ch:freedirect-freeapi}
\label{ch:freedirect-deep-dive}

CNA's \texttt{FREEDIRECT} renderer sits on two compatibility libraries. \texttt{free-direct}
reimplements a narrow DirectX~3-era DirectDraw, DirectSound, and DirectPlay surface;
\texttt{free-api} supplies the Win32-shaped types and services below it using SDL3. Neither is
a general emulator, and CNA's native \texttt{DIRECTX1} through \texttt{DIRECTX7} renderers do
not use either library.

\section{A game-driven boundary}

Free-direct's original scope is derived from calls made by two games: \emph{Speedy Blupi}
through free-eggbert, and \emph{Planet Blupi}. A third game cannot assume that a familiar
DirectX symbol exists merely because the header name does. It needs its own call-site audit and
an explicit decision about widening the library.

The audited public headers make that boundary measurable. Across \texttt{ddraw.h},
\texttt{dplay.h}, and \texttt{dsound.h}, all 95 public methods carry a status tag:

\section{Three DirectX subsystems, no Direct3D}

\textbf{DirectDraw} owns CPU pixel buffers, primary and offscreen surfaces, clipping, source
color keys, palettes, \texttt{Blt}/\texttt{BltFast}, \texttt{Lock}/\texttt{Unlock}, and SDL
texture upload on \texttt{Flip}. Surface registration allows renderer invalidation. It is the
deepest and most directly exercised part of CNA's 2D compositor.

\textbf{DirectSound} opens a real SDL3 audio device and stream behind a shared, mutex-protected
device. Static PCM buffers, volume, and constant-power pan are implemented; volume uses
$10^{cB/2000}$. The subsystem enforces a 64 MiB buffer ceiling and contains a deliberate
\texttt{PCMWAVEFORMAT} versus \texttt{WAVEFORMATEX} layout correction. Some playback controls
remain narrower than Microsoft's device model.

\textbf{DirectPlay} implements sessions, players, unicast, broadcast, and host-side relay
behind a transport interface. A default build has only in-process loopback. Real UDP peers and
LAN discovery require \texttt{FREE\_DIRECT\_ENABLE\_ENET}, which is OFF by default and adds
ENet privately. Its packets are FreeDirect-to-FreeDirect, not Microsoft DirectPlay wire
compatibility.

There is no Direct3D source or public interface at all. This library is ``DirectX~3'' only in
the era-bundle sense; its graphics path is DirectDraw 2D.

\section{The two libraries form a one-way dependency}

Free-direct adds its sibling \texttt{../free-api} when no \texttt{free-api} target already
exists, disables free-api's tests, and links \texttt{free-api::free-api} publicly. Free-api
does not depend on free-direct. It supplies roughly 80 \texttt{extern "C"} \texttt{WINAPI}
declarations across flat Win32-named headers and a real \texttt{windows.h} umbrella.

The public types deliberately do not expose SDL. Internally an \texttt{HWND} represents an
\texttt{SDL\_Window*} cast through \texttt{void*}; message translation, GDI-lite buffers,
files and paths, timers, MCI/MIDI playback, joystick input, string resources, and diagnostics
all translate to SDL-backed machinery. MIDI uses a shared audio stream, a mixing thread, and
vendored TinySoundFont/TinyMidiLoader. Free-api itself links SDL3, SDL3\_image, and SDL3\_mixer,
but neither ENet nor sharp-runtime.

Only three bridge functions are explicitly designed for free-direct:
\texttt{FreeApiCreateSurfaceDC}, \texttt{FreeApiDestroySurfaceDC}, and
\texttt{FreeApiSetWindowFullscreen}. Keeping those in \texttt{free\_api\_bridge.h} names the
scope exception instead of letting free-direct reach arbitrarily into private implementation.

\section{CNA is the odd consumer}

Free-eggbert and Planet Blupi add free-api first and then free-direct. CNA adds only free-direct
when \texttt{CNA\_GRAPHICS\_RENDERER=FREEDIRECT}; the public link edge pulls free-api into the
final closure transitively. CNA is therefore a real third consumer of free-api even though its
own build file never calls \texttt{add\_subdirectory} for it.

CNA's renderer is not a thin adapter. Its 1{,}374-line implementation creates DirectDraw
surfaces, performs locked pixel write/read/clear operations, composites quads on the CPU, and
maintains a shadow-backbuffer resize transaction with failure injection. Eight registered CNA
test binaries exercise it under SDL's dummy video driver and inspect shadow-buffer pixels.

\section{The \texttt{fopen} macro is a real containment cost}

Free-api's \texttt{windows.h} defines \texttt{fopen} as \texttt{free\_api\_fopen}. Because
free-direct's \texttt{ddraw.h} includes that umbrella, exposing \texttt{ddraw.h} from a CNA
public header would rewrite every later \texttt{fopen(...)} token in the translation unit.
CNA contains the hazard with pimpl: \texttt{FreeDirectRenderer.hpp} does not include
\texttt{ddraw.h}; the implementation file owns all DirectDraw types.

\begin{lstlisting}
// Public header: no ddraw.h, no free-api windows.h, no fopen macro.
class FreeDirectRenderer final : public IGraphicsRenderer {
    struct Impl;
    std::unique_ptr<Impl> impl_;
};

// Implementation file only:
#include <ddraw.h>
struct FreeDirectRenderer::Impl { /* IDirectDraw state */ };
\end{lstlisting}

This is more than ``keep headers small.'' It is a preprocessor quarantine around a second-level
dependency whose public compatibility contract intentionally includes global Win32 macros.

\section{FREEDIRECT is not DIRECTX3}

CNA's \texttt{DIRECTX1}, \texttt{DIRECTX2}, \texttt{DIRECTX3}, \texttt{DIRECTX5},
\texttt{DIRECTX6}, and \texttt{DIRECTX7} renderers use the real Microsoft/MinGW/Wine DirectDraw
SDK and link \texttt{ddraw}/\texttt{dxguid}; they deliberately do not use free-direct. The
SDL-backed renderer was itself named \texttt{DIRECTX3} until 2026-08-04, when it became
\texttt{FREEDIRECT} precisely to remove this ambiguity.

Selector spelling therefore determines two different dependency graphs:

\begin{lstlisting}
FREEDIRECT -> CNA FreeDirectRenderer -> free-direct -> free-api -> SDL3
DIRECTX3   -> CNA DirectX3Renderer  -> MinGW/Wine ddraw + dxguid
\end{lstlisting}

The same public \texttt{ddraw.h} spelling can resolve to different providers under those
graphs, which is why source-path and target evidence matter more than API-name resemblance.

\section{Verification boundaries}

Free-direct has nine default CTest registrations, ten with ENet, using a hand-rolled
\texttt{CHECK} mechanism. Compile-only header tests and a shell hygiene gate prevent SDL or
ENet identifiers from leaking into public headers. Tests default OFF. The DirectPlay suite
also records that enabling ENet makes 29 of 61 loopback-shaped checks fail by design because
the timing model changes; a transport toggle is not a free strengthening of the same oracle.

Free-api has 29 CTest registrations: 20 C\texttt{++} programs and nine CMake-level tests,
including negative controls for string-table extraction and public-surface scans. They are ON
standalone and OFF when embedded. The suite exercises SDL-to-\texttt{WM\_*} translation,
message filtering, timers, GDI bounds, resource strings, MCI/MIDI, joystick, and quiet logging.

Test volume did not prevent a cautionary 2026-07-18 sequence. A nine-finding re-audit was
immediately followed by two regressions introduced by its changes: a startup abort from
reentrant static initialization and real memory growth from bitmap pooling. Users found both,
not the 29-test suite. The episode is a useful reminder that an audit patch changes the system
under audit; regression risk belongs inside the review, not after it.

The correct scope statement is thus precise. These libraries reproduce the calls their games
and CNA currently need, with unusually visible status metadata and meaningful tests. They are
not Wine, a complete Win32 SDK, hardware-accurate DirectX emulation, or a general foundation for
arbitrary DirectX~3 software.
