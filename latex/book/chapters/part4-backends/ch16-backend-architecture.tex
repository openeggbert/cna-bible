\chapter{Backend Architecture}
\label{ch:backend-architecture}

Every backend chapter that follows implements the same contract. This chapter covers that
contract once --- the interfaces, the shared parameter struct, and the build-time selection
mechanism --- so the nine backend-specific chapters ahead can spend their time on what
actually differs, not on repeating the shape they all share.

\section{One header, not several}

Despite \cnaclass{IGraphicsBackend} being described throughout this book as ``the backend
contract layer,'' it is worth being precise: the entire contract lives in a single header,
\texttt{include/\allowbreak{}CNA/\allowbreak{}Internal/\allowbreak{}Backends/\allowbreak{}Common/\allowbreak{}IGraphicsBackend.hpp} --- roughly a thousand
lines, not a family of separate \texttt{ISpriteBatchBackend.hpp} / \texttt{ITextureBackend.hpp}
files. Eleven interface classes live inside it, all in
\texttt{namespace CNA::Internal::Backends}:

\cnaclass{IGraphicsBackend} itself is the large one: device lifecycle
(\texttt{Clear} / \texttt{Present}/viewport and presentation-mode management), native handle
access (\texttt{GetWindowInternal()} / \texttt{GetRendererInternal()} --- both pure virtual,
and both carry a comment flagging the \texttt{SDL\_Window*} / \texttt{SDL\_Renderer*} return
types as ``should be abstracted later''), resource factories for every GPU object type in
Part~III, render-target binding, per-state-object apply methods, the full 3D draw dispatch
(\texttt{DrawColoredPrimitives}, the effect-aware \texttt{DrawPrimitivesEx} family, instanced
draws), and a capability-query mechanism (\S\ref{sec:graphicscapability} below). A single,
project-wide design choice worth internalizing before reading any backend chapter: nearly
every optional method on this interface \textbf{defaults to a safe no-op or a null return}
rather than requiring every backend to implement everything. \texttt{CreateEffectBackend()}
defaults to \texttt{nullptr} (``backends that do not support programmable shaders'');
\texttt{CreateOcclusionQuery()} defaults to \texttt{nullptr}; every state-application method
defaults to doing nothing at all. This is a deliberate ``graceful capability degradation''
design, and every backend chapter's own ``degrades/gap/blocked'' distinctions in Part~IV rest on it: a feature
that silently degrades to a no-op reads differently in an audit than one that throws, even
though both mean ``not implemented here.''

\subsection{ISpriteBatchBackend, and where Chapter~\ref{ch:spritebatch}'s transform bug actually lived}

Only five of \cnaclass{ISpriteBatchBackend}'s nine methods are pure virtual ---
\texttt{Begin()}, \texttt{End()}, and the three \texttt{Draw} overloads
(\texttt{float x, float y}; destination-plus-source-rectangle; and a fully-parameterized
rotation/origin/effects/depth form). \texttt{SetTransformMatrix}, \texttt{SetCustomEffect},
\texttt{SetSamplerFilter}, and \texttt{SetSamplerAddressMode} all default to a plain, silent
no-op body in the interface itself. This is the exact mechanism behind
Chapter~\ref{ch:spritebatch}'s own worst SDL\_RENDERER finding: a backend that simply never
overrides \texttt{SetTransformMatrix} is not violating the interface contract in any way a
compiler could catch --- it is using the interface exactly as designed, ``graceful capability
degradation'' silently reached its most literal form, a \texttt{Begin(transformMatrix)} call
whose matrix argument reaches the backend and is discarded with zero indication anything was
skipped. Reading this interface's own defaults is why that bug reads as an architecturally
expected failure mode, not a surprising one, and it also names a real, genuine gap in the
capability-query mechanism covered next: \cnaclass{GraphicsCapability} (below) has no value at
all for ``does this backend actually honor a \cnaclass{SpriteBatch} transform matrix,'' so a
caller has no way to \emph{ask} before hitting this specific silent no-op --- unlike the eight
capabilities that mechanism does cover.

\subsection{IRenderTargetBackend: where Chapter~\ref{ch:textures-rendertargets}'s honest defaults actually live}

Reading \cnaclass{IRenderTargetBackend}'s own interface definition directly explains
\emph{why} several of Chapter~\ref{ch:textures-rendertargets}'s per-backend render-target
findings take the specific shape they do, rather than being independent per-backend choices:
\texttt{GetMultiSampleCount()} defaults to returning \texttt{0}, and
\texttt{HasRealDepthBuffer(bool depthFormatWasRequested)} defaults to simply echoing back
whatever was requested. Vulkan and BGFX ``honestly reporting \texttt{MultiSampleCount = 0}''
is not a special case either backend had to write --- it is what happens automatically by
\emph{not overriding} this method at all, exactly the same ``graceful capability degradation''
default-no-op pattern this chapter opened with, applied here to a getter rather than a
command. \textbf{SDL\_RENDERER} is the one backend that does override
\texttt{HasRealDepthBuffer} specifically to return \texttt{false} unconditionally (Task~708)
--- the one case in this whole family of defaults where the honest answer requires active
code rather than falling out of inaction, because the naive default (echoing the request back)
would otherwise silently claim a depth buffer exists on a backend whose 2D-only render targets
never allocate one.

\subsection{IEffectBackend and IOcclusionQueryBackend: capability-gated by construction}

These are the two thinnest interfaces in the table above, and both connect directly to
\cnaclass{GraphicsCapability} values already named in this chapter.
\cnaclass{IOcclusionQueryBackend} is fully pure virtual --- \texttt{Begin()}, \texttt{End()},
\texttt{IsComplete()}, \texttt{PixelCount()} --- with no default-no-op escape hatch at the
interface level at all; a backend that does not support occlusion queries simply never
constructs one in the first place, since \texttt{CreateOcclusionQuery()} on
\cnaclass{IGraphicsBackend} itself is what defaults to \texttt{nullptr}
(\cnaclass{GraphicsCapability::OcclusionQuery} is the flag a caller checks before ever
reaching this interface at all).

\cnaclass{IEffectBackend} takes the opposite approach for a subtler reason worth reading
carefully: only \texttt{CompileProgram}, \texttt{Bind}, \texttt{Unbind}, \texttt{IsValid}, and
\texttt{GetCompileError} are pure virtual --- every one of its \texttt{SetUniform*} setters
(\texttt{Float}, \texttt{Int}, \texttt{Vec2/3/4}, \texttt{Mat4}, and the array forms) defaults
to a silent no-op body in the interface itself, the identical shape as
\cnaclass{ISpriteBatchBackend}'s \texttt{SetTransformMatrix} default from this chapter's own
\texttt{ISpriteBatchBackend} section above. This means a backend could, in
principle, compile a \cnaclass{ShaderEffect}'s program successfully (\texttt{IsValid()}
returning \texttt{true}) while silently dropping every single uniform value a game sets on it
--- exactly the kind of ``it compiles and something appears on screen'' risk
Chapter~\ref{ch:shader-fx-gap}'s own \texttt{IsEffectValid()} worked example already warned
readers to check for, extended one level deeper here: a valid program is not the same
guarantee as a program that actually receives the uniforms it was given. Backends that ship
\cnaclass{ShaderEffect} support do \emph{not} uniformly override the full setter set; this is a
real, observed boundary, not merely a hypothetical one. EasyGL supplies every
scalar, vector, matrix, array, and 2D/cube/volume texture hook. D3D11 and D3D12 supply the
scalar/vector/matrix family but inherit both array no-ops and every texture no-op; D3D9 has
the same setter boundary. Their \cnaclass{SpriteBatch} paths bind only the primary texture
expected by the fixed shader contract. Vulkan and SDL GPU likewise implement only their fixed
scalar/vector/matrix slots. Headless records scalar/vector/matrix/array updates and a 2D
texture bind for logic tests, but cannot prove a pixel result. Most strikingly, Software
returns a valid effect while deliberately executing none of the supplied source and
discarding every setter. Chapter~\ref{ch:shader-fx-gap} gives the full live matrix; the
architectural lesson here is that each method on this permissive interface is an independent
capability, even after compilation succeeds.

\subsection{Buffer streaming: one ignored constructor flag, four real hint mappings}

\cnaclass{IVertexBufferBackend} has two permissive defaults that originally made the public
buffer family look simpler than it now is. \path{SetDataWithOptions()} discards its
\cnaclass{SetDataOptions} argument and calls plain \texttt{SetData()}; and
\path{SetVertexDeclaration()} discards the caller's element list. The index interface has
the analogous \path{SetData16WithOptions()} / \path{SetData32WithOptions()} forwarding
defaults. These methods are all reachable on the ten 3D-capable implementations, unlike the
unreachable \texttt{SetData32} throw discussed next.

The shared public constructors impose one universal limit before that backend split. Each
\texttt{Dynamic*} class passes \texttt{dynamic=true} to its protected base constructor, but
that constructor leaves the parameter unnamed and calls the same factory as the static class.
The type therefore never selects a different allocation merely by being dynamic. That does
\emph{not} mean every upload hint is ignored:

EasyGL has the strongest public pixel proof:
\path{easygl_dynamic_buffer_stress_test.cpp} cycles all three enum values over twelve
successive colored-quad frames and reads the center pixel each time. SDL GPU's smoke test
calls both distinct paths for vertex and index buffers but checks only the resulting count,
so the native \texttt{cycle} distinction is established by source, not by that assertion.
WebGPU's own plan still leaves its option-specific buffer tests open.

One bug sits above every row in this table. The options-taking public wrappers pack and upload
their bytes but never update the shared \cnaclass{VertexBuffer}/\cnaclass{IndexBuffer}
\texttt{cpuShadow\_}. Consequently a non-\texttt{WriteOnly} dynamic buffer's inherited
\texttt{GetData()} cannot return the data just uploaded: on a fresh instance the empty shadow
produces \texttt{ArgumentOutOfRangeException}; after an older ordinary upload it can return
stale data. Chapter~\ref{ch:textures-rendertargets} gives the caller-facing consequence.

The declaration default has one live override too. \path{VertexBuffer::SetDataRaw()} sends
its element list through \path{SetVertexDeclaration()} before upload. EasyGL consumes all
twelve \cnaclass{VertexElementFormat} shapes and binds GLSL attribute locations by declaration
order; the other nine constructible implementations inherit the no-op and remain dependent on
their fixed stride/effect combinations. The EasyGL test is deliberately discriminating even
after the fixed layout family grew: its custom record is 48 bytes, the same total as CNA's PBR
vertex, but has different offsets and a trailing color. Correct diagnostic pixels therefore
prove the declaration won over the fixed 48-byte interpretation.

\subsection{Texture2D updates: one dead default and one live silent discard}
\label{sec:texture2d-update-matrix}

\cnaclass{ITextureBackend} gives both \texttt{UpdatePixels()} and
\texttt{UpdatePixelsLevel()} empty default bodies. They look symmetric in the header, but
the current factory graph makes them materially different. Every concrete object returned by
any backend's \texttt{CreateTexture()} overrides level~0 \texttt{UpdatePixels()} (ASCII
returns SDL\_RENDERER's object), so that first no-op is unreachable today. The mip-level
default remains live on SDL GPU. Software and Headless override it too, but deliberately
discard the bytes or record only a trace, respectively.

The public routing matters before reading the table. Whole-texture
\texttt{SetData(Color*, count)} recreates the resource and never calls either update hook.
Only the detailed level/rectangle overload reaches them: level~0 patches the CPU shadow and
re-uploads that complete level through \texttt{UpdatePixels()}, while a higher level calls
\texttt{UpdatePixelsLevel()}. Ordinary \texttt{Texture2D::GetData()} then reads the same CPU
shadow, not the GPU object, so a public SetData/GetData round trip is not proof that either
hook changed sampled content.

WebGPU's level~0 behavior is a deliberate compatibility difference, not merely an
implementation technique. It renders a linear downsample from each level into the next
whenever level~0 changes, including at construction. FNA and CNA's other ordinary-texture
implementations expect authored/content-pipeline mip data instead. Consequently WebGPU gives
an otherwise-empty chain useful pixels automatically, but a later level~0 write also
regenerates over higher levels authored before it.

The test boundary is especially important for EasyGL and Vulkan's identically registered
\path{easygl_texture2d_mip_test.cpp}: the file itself states ``No framebuffer readback ---
pure CPU shadow buffer.'' The separate texture-filter tests are the GPU proof. D3D11/12 and
WebGPU instead bypass the public shadow and read native subresources directly. This is the
same audit rule the volume/cube matrix below applies to Headless's misleadingly named
``round-trip'' tests: follow the assertion to the storage layer it actually observes.

\subsection{Volume and cube readback: the no-op default mostly became real}
\label{sec:texture-volume-readback-matrix}

\cnaclass{ITexture3DBackend::GetData()} and
\cnaclass{ITextureCubeBackend::GetData()} both default to an empty body. The public wrappers
make the consequence subtler than ``the caller is untouched.'' When a backend object exists,
each wrapper allocates a zero-initialized RGBA byte vector, calls the backend, then converts
the whole requested element range back to \cnaclass{Color}. An inherited no-op therefore
\emph{overwrites} that destination range with transparent black. When a resource factory
returns \texttt{nullptr}, by contrast, the wrapper returns before allocating or converting
anything and really does leave the caller's destination unchanged.

The ordinary-resource columns below cover \cnaclass{Texture3D} and
\cnaclass{TextureCube}. The third is separate because \cnaclass{RenderTargetCube} inherits
the same public \texttt{GetData()} but supplies a different backend object:

The eight ordinary GPU implementations are not CPU-shadow echoes. EasyGL attaches the
requested slice or face to a temporary framebuffer and calls \texttt{glReadPixels}; Vulkan
copies the requested image subresource into host-visible staging memory; D3D9 locks its
managed cube/volume resource, while D3D11 and D3D12 use staging/readback resources with
native row and slice pitches; WebGPU maps a staged copy asynchronously; and SDL GPU waits on
a download transfer and fence. BGFX cannot mark an ordinary sampled source
\texttt{READ\_BACK}, so it blits the requested region into a temporary transfer texture and
advances frames until \texttt{readTexture()} completes. If the selected renderer lacks its
required blit/readback capabilities, that path logs and returns; the public zero-initialized
staging vector then makes the result transparent black.

The proof is correspondingly stronger than ``did not throw.'' EasyGL, Vulkan, and BGFX
share exact slice, off-origin rectangle, and mip round trips; WebGPU's public checks
distinguish all six faces, a non-origin rectangle, and mip data, plus separate volume slices,
voxel, and mip cases. SDL GPU checks distinct slices/faces and authored/generated mip
retention. D3D9/11/12 smoke tests compare exact subregion bytes (D3D9 first gates its
volume/cube cases on the real device caps). Software's cube storage is source-proven and its
environment-map sampling is pixel-proven, but no dedicated public exact
\texttt{TextureCube::GetData()} assertion was found.

Headless is the cautionary counterexample. The first comments in
\path{headless_resource_backends_test.cpp} call its volume and cube checks ``round-trips,''
but the implementation deliberately discards uploads and returns zero placeholders. The
actual assertions only prove that calls on two faces and one volume do not throw; they never
compare returned colors. A test title or introductory comment is not evidence when the
assertion body establishes a weaker contract.

\subsection{RenderTargetCube: one inherited upload, two independent transition traps}
\label{sec:rendertargetcube-default-contracts}

\cnaclass{RenderTargetCube} inherits \cnaclass{TextureCube}'s complete public
\texttt{SetData()} family. FNA leaves that inherited call live and forwards it to
\texttt{FNA3D\_SetTextureDataCube()}, including when the texture was created as a render
target. CNA's backend contract instead redeclares \texttt{SetData()} on
\cnaclass{IRenderTargetCubeBackend} with an empty default body and the comment ``render targets
do not support CPU-side SetData.'' Only EasyGL overrides it. The shared public wrapper still
performs face, rectangle, mip-level, pointer, and count validation and still converts the
requested \cnaclass{Color} range to RGBA bytes before making that call. Consequently a valid
upload reports success everywhere: EasyGL changes the requested face/subregion; every other
constructed cube target silently discards the bytes. Software and the four 2D-only backends
construct no cube target, so their public object has a null backend and discards the upload
one layer earlier. No dedicated test calls \texttt{SetData()} on a
\cnaclass{RenderTargetCube}; the EasyGL result and every no-op are source-proven only.

Target switching is a separate default. \cnaclass{IGraphicsBackend}'s
\texttt{SetRenderTargetCubeFace(rt, face)} calls
\texttt{rt->BindAsRenderTargetFace(face)} when non-null, but on null merely delegates to
\texttt{SetRenderTarget2D(nullptr)}. It never remembers or calls the outgoing cube target's
\texttt{UnbindAsRenderTarget()}. That is harmless only when the backend either overrides the
method, tracks cube state elsewhere, or finalizes each face without an unbind callback:

\texttt{BindAsRenderTargetFace()} followed by \texttt{UnbindAsRenderTarget()}. Those tests
establish that the resolve and mip implementations work \emph{when invoked}; no D3D11/12 test
was found that routes a cube through \cnaclass{GraphicsDevice}'s public cube-target overload
and then back through the public null-target call. They therefore cannot prove the public
transition that currently fails to invoke them. This is the same audit lesson as the Headless
``round-trip'' above: inspect the call layer the test exercises, not only its feature name.

\subsection{IIndexBufferBackend::SetData32: a defensive throw traced out to dead code}

Not every default in this file is a silent no-op. \cnaclass{IIndexBufferBackend}'s
\texttt{SetData32} defaults to throwing a plain \texttt{std::runtime\_error}
(\texttt{"SetData32 not supported by this backend"}) rather than quietly doing nothing --- the
opposite failure mode from every default this chapter has covered so far. Grepping every
backend's own implementation directory shows exactly four backends never override it:
\texttt{SDL\_RENDERER}, \texttt{ASCII}, \texttt{CANVAS}, and \texttt{DX3}; the other ten
(\texttt{EasyGL}, \texttt{Vulkan}, \texttt{BGFX}, \texttt{D3D9}, \texttt{D3D11}, \texttt{D3D12},
\texttt{WebGPU}, \texttt{SdlGpu}, \texttt{Software}, and the internal \texttt{Headless} test
backend) all supply a real one.

Tracing where that default would actually fire tells a reassuring story rather than an
alarming one, though only once actually traced rather than assumed: all four non-overriding
backends are the project's 2D-only backends, and every one of them already refuses to
construct \emph{any} index buffer at all, 16-bit or 32-bit, at its own
\texttt{CreateIndexBuffer16} / \texttt{CreateVertexBuffer} factory call --- confirmed directly
in \texttt{Dx3GraphicsBackend.cpp} and \texttt{CanvasGraphicsBackend.cpp} (\texttt{"does not
support 3D"} thrown by name for both calls) and in a real, dedicated regression test for
\texttt{SDL\_RENDERER} (\texttt{sdlrenderer\_buffer\_construction\_throws\_test.cpp}, Task~723)
that pins the exact thrown message for a \texttt{ThirtyTwoBits} \cnaclass{IndexBuffer}
construction --- and that message is \texttt{CreateIndexBuffer16}'s own, not a distinct
32-bit-specific one, since \texttt{CreateIndexBuffer32} is never separately overridden on this
backend either and simply delegates to the 16-bit path's throw. \texttt{ASCII} inherits the
identical no-3D-support story from \texttt{SDL\_RENDERER} underneath it
(Chapter~\ref{ch:what-is-cna}'s own verification-scale table already notes this inheritance).
The practical consequence: \cnaclass{IIndexBufferBackend}'s own \texttt{SetData32} default can
never actually fire in this project today --- every backend that would reach it fails earlier,
at construction, for an unrelated and already-well-tested reason, and every backend that
survives construction already supplies its own real override. It is defensive code with no
live call path behind it right now, not a currently-reachable gap --- worth recording precisely
as that, rather than either dismissing it as obviously dead without checking or citing it as an
active risk without tracing where it actually leads.

\section{GpuDrawParams: already covered, worth remembering here}

Chapter~\ref{ch:stock-effects} already introduced \cnaclass{GpuDrawParams} in full --- the
single struct \texttt{Effect::FillGpuDrawParams()} populates and every backend's
\texttt{DrawPrimitivesEx} / \texttt{DrawIndexedPrimitivesEx} consumes. It is worth restating
here only because it is the concrete mechanism by which ``a stock effect draws identically
across twelve backends'' is actually achieved: the effect layer never talks to a backend
directly about lights, fog, or skinning palettes --- it fills one struct, and each backend's
own draw dispatch decides how to turn that struct into real GPU state.

\section{GraphicsCapability: ask, don't catch}
\label{sec:graphicscapability}

Rather than requiring game code to attempt an operation and catch an exception to discover
whether a backend supports it, \cnaclass{GraphicsCapability} is a small enum ---
\texttt{ThreeD}, \texttt{DepthStencilBuffer}, \texttt{MultiSampleAntiAliasing},
\texttt{MultipleRenderTargets}, \texttt{AnisotropicFiltering}, \texttt{WireFrame},
\texttt{OcclusionQuery}, \texttt{CustomEffects} --- queryable via
\texttt{GraphicsDevice::\allowbreak{}SupportsCapability\allowbreak{}(GraphicsCapability)}. The default implementation
returns \texttt{true} for everything; a 2D-only backend like \texttt{SDL\_RENDERER}
(Chapter~\ref{ch:sdl-renderer}) overrides this to honestly report what it cannot do, rather
than accepting a 3D draw call and throwing only once the call actually arrives.

\begin{lstlisting}
const auto backend = device.GetGraphicsBackendType();
const bool knownAscii3DFalsePositive =
    backend == GraphicsBackendType::Ascii;
if (device.SupportsCapability(GraphicsCapability::ThreeD) &&
    !knownAscii3DFalsePositive) {
    DrawSceneWith3DModels();
} else {
    DrawFlat2DFallbackScene(); // e.g. running on SDL_RENDERER or CANVAS
}

const bool knownOcclusionFalsePositive =
    backend == GraphicsBackendType::WebGPU ||
    backend == GraphicsBackendType::SdlGpu ||
    backend == GraphicsBackendType::Software ||
    backend == GraphicsBackendType::Ascii;
if (!device.SupportsCapability(GraphicsCapability::OcclusionQuery) ||
    knownOcclusionFalsePositive) {
    // Skip GPU occlusion culling entirely rather than constructing an OcclusionQuery
    // whose factory would return nullptr or throw on these known exceptions.
}
\end{lstlisting}

This is precisely the ``ask, don't catch'' pattern this section's own title promises, and a
Chapter~\ref{ch:graphicsdevice} finding is worth recalling here as the reason it must be used
deliberately rather than assumed reliable everywhere: \cnaclass{MultipleRenderTargets}
is one of the eight values this mechanism covers, but no backend's \texttt{SupportsCapability}
override actually gates on it, so it silently returns \texttt{true} even on backends (like
\texttt{SOFTWARE}) where a real MRT draw demonstrably fails --- a capability flag that exists,
but that this specific query cannot yet be trusted to answer honestly for.

The source audit confirms further failures of that default-true design. First,
\texttt{ASCII} is 2D-only and forwards its executable 3D calls to SDL renderer's throwing
implementation, but it has no \texttt{SupportsCapability()} override of its own; unlike
\texttt{SDL\_RENDERER}, \texttt{DX3}, and \texttt{CANVAS}, it therefore reports
\texttt{ThreeD=true}. Second, \texttt{CustomEffects} reports true on BGFX, WebGPU, ASCII, and
Software despite four different non-support shapes: an always-invalid compiled object, a null
factory plus a throwing \cnaclass{SpriteBatch}, the same null/throw combination through the
ASCII decorator, and a valid-looking Software object whose source is never executed. Thus
\texttt{OcclusionQuery} is a third confirmed case: WebGPU, SDL GPU, and Software inherit a
null factory, while ASCII forwards to SDL renderer's throwing factory, but all four report
\texttt{true}. Thus ``ask, don't catch'' is the intended API, not yet a universal guarantee.
A caller targeting one of these known exceptions needs the explicit guards above and, for
custom effects, the backend-specific boundary documented in
Chapter~\ref{ch:shader-fx-gap}.

\section{Build-time selection}

\texttt{cmake/BackendSelection.cmake} is where the backend list from
Chapter~\ref{ch:building-cna} is actually enumerated: the \texttt{CNA\_GRAPHICS\_BACKEND}
cache variable's \texttt{STRINGS} property lists all fourteen recognized values
(\texttt{SDL\_RENDERER}, \texttt{EASYGL}, \texttt{BGFX}, \texttt{VULKAN}, \texttt{WEBGPU},
\texttt{HEADLESS}, \texttt{SOFTWARE}, \texttt{D3D11}, \texttt{D3D12}, \texttt{CANVAS},
\texttt{ASCII}, \texttt{DX3}, \texttt{D3D9}, and \texttt{SDL\_GPU} ---
Chapter~\ref{ch:sdlgpu-backend}'s own dedicated coverage, added later in this book's history
than the other thirteen), and fourteen corresponding boolean
options exist alongside it --- if more than one is somehow set \texttt{ON} at once,
configuration fails outright with ``Exactly one backend option must be ON.'' The default is
itself platform-conditional: \texttt{EASYGL} on Linux or Emscripten, \texttt{SDL\_RENDERER}
everywhere else.

Several backends carry hard, configure-time platform gates rather than soft warnings:
\texttt{D3D9} / \texttt{D3D11} / \texttt{D3D12} fail configuration outright unless
\texttt{CMAKE\_SYSTEM\_NAME} is \texttt{Windows} (native or MinGW-w64 cross-compiled) ---
the comment in the CMake script is blunt about why: ``d3d11.h/d3d12.h/dxgi.h do not exist
elsewhere.'' \texttt{CANVAS} fails configuration outright unless building under Emscripten,
since HTML \texttt{<canvas>} is a browser DOM API with no meaning anywhere else.
\texttt{EASYGL} and \texttt{BGFX} both emit a soft warning (not a hard failure) if configured
outside Linux. \texttt{EASYGL} and \texttt{DX3} both require their respective sibling
checkouts (\texttt{../easy-gl}, \texttt{../free-direct}) to exist at all, hard-erroring
otherwise; \texttt{BGFX} instead fetches \texttt{bkaradzic/bgfx.cmake} directly via CMake's
\texttt{FetchContent}.

\texttt{cmake/BackendLibraries.cmake} wires the resulting per-backend link libraries and
contains two architectural details worth knowing before Chapter~\ref{ch:canvas-ascii-backends}:
the \texttt{ASCII} backend is built by reusing \texttt{SDL\_RENDERER}'s own real \texttt{.cpp}
sources as a separate static library, compiled \emph{without} \texttt{CNA\_BACKEND\_SDL\_RENDERER}
defined so its own \texttt{CreateGraphicsBackend()} factory is compiled out and cannot clash
with ASCII's own factory --- confirming in build-system terms what
Chapter~\ref{ch:canvas-ascii-backends} states in prose: ASCII is composition around
SDL\_Renderer, not a reimplementation. And \texttt{D3D9}'s effect-compilation code
(\texttt{D3D9EffectBackend} / \texttt{D3D9ConstantTable}) is deliberately isolated into its own
static library specifically so that only that isolated library links against
\texttt{d3dcompiler} --- keeping the stock D3D9 rendering pipeline itself free of that
dependency, unlike \texttt{D3D11} / \texttt{D3D12}, which link \texttt{d3dcompiler}
unconditionally into their whole backend target.

\section{One factory function per backend}

Whichever backend is selected at configure time compiles exactly one implementation of
\texttt{std::unique\_ptr\allowbreak{}<IGraphicsBackend>\allowbreak{} CreateGraphicsBackend(const
GraphicsBackendCreateArgs\&)}, gated behind a \texttt{\#ifdef CNA\_BACKEND\_*} matching the
compile definition \texttt{BackendSelection.cmake} set. \cnaclass{GraphicsBackendCreateArgs}
itself carries the window handle, virtual resolution, presentation mode, context-recovery
flag, multisample count, swap interval, and --- as \texttt{NOXNA} additions introduced
alongside the \texttt{D3D9} backend --- back-buffer/depth-stencil format, fullscreen flag,
and graphics profile, each documented as a field ``every existing backend except D3D9 may
ignore'': a direct, structural acknowledgment that \texttt{D3D9} is the one backend that
actually consults these values the way a real device negotiation would.

With the shared contract established, the next nine chapters cover what each backend
actually does with it.
