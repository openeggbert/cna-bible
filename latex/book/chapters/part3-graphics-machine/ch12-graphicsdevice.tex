\chapter{GraphicsDevice and the Rendering Pipeline}
\label{ch:graphicsdevice}

\cnaclass{GraphicsDevice} is CNA's public rendering hub. It owns the selected renderer and
window when applicable, stores public pipeline state, tracks resources for ordered teardown,
normalizes render-target and vertex bindings, and forwards draws. That sequence matters: public
state can be valid even when a family ignores the corresponding native operation. Figure
\ref{fig:graphicsdevice-flow} separates those layers.

\input{figures/fig-graphicsdevice-flow.tex}

This chapter owns the shared device contract. Resource classes are detailed in
Chapters~\ref{ch:textures-rendertargets}--\ref{ch:vertex-streams-capabilities}; renderer defaults
and divergences are in Chapter~\ref{ch:renderer-contract}.

\section{Construction and native lifetime}

The XNA-shaped constructor accepts a \cnaclass{GraphicsAdapter}, \cnaclass{GraphicsProfile}, and
\cnaclass{PresentationParameters}. The CNAEXT default constructor delegates with the default
adapter, \texttt{Reach}, and default presentation parameters. It is windowless only when the
compiled family is inherently windowless (including \texttt{HEADLESS}, \texttt{SOFTWARE},
\texttt{STUB}, and \texttt{PORTABLEGL}). D3D12's runtime \texttt{HeadlessEXT} path instead
requires explicit presentation parameters. A default constructor on a normal windowed family
creates an SDL window, usually $1024\times768$ when no size was requested.

\cnaclass{Game} owns a device value member before a derived game's
\cnaclass{GraphicsDeviceManager} exists. During initialization the manager reconfigures that
same device through \texttt{Reset}; ordinary game code does not construct a second device.

\subsection{Window, renderer, and presentation setup}
\label{sec:private-lifecycle}

The private construction path is observable through its ordering:

\begin{enumerate}
  \item Initialize SDL video unless the compiled or requested path is windowless.
  \item Create a window, attach a caller-owned \texttt{DeviceWindowHandle}, or retain null.
        Both CNA-owned and attached windows are published to mouse and text-input services.
  \item Apply SDL window size/fullscreen state.
  \item Build \texttt{GraphicsRendererCreateArgs} and call the selected family factory.
  \item Normalize reported backbuffer/depth formats, query the renderer's logical and physical
        viewport, and apply initial blend, depth/stencil, and rasterizer state.
\end{enumerate}

An attached window is borrowed: CNA clears matching input handles at teardown but destroys the
window only when \texttt{ownsWindow\_} is true. Chapter~\ref{ch:renderer-contract},
\S\ref{sec:backend-native-handle-boundary}, covers the remaining native-handle rules.

\begin{limitationnote}
Construction is not fully transactional. After SDL video initialization, a later window,
renderer, or initial-state exception can bypass \cnaclass{GraphicsDevice}'s destructor and leak
the raw owned window, published input handle, or video-subsystem lease. Teardown also calls
\texttt{SDL\_QuitSubSystem(SDL\_INIT\_VIDEO)} even for a device that skipped initialization,
which can release another client's reference. The located tests establish windowless operation,
not mixed-client reference accounting or injected construction failure.
\end{limitationnote}

\label{sec:property-surface}

The property surface is easier to use when grouped by ownership and forwarding:

Assigning \texttt{Textures[0]} alone does not make a draw sample that texture. A stock effect
populates \cnaclass{GpuDrawParams}; \cnaclass{ShaderEffect} uses its own texture setters. The
device's texture collections enforce slot, disposal, and active-target invariants, but they are
not a general shader binding mechanism.

\subsection{Viewport and scissor}
\label{sec:graphicsdevice-viewport-scissor}

Both setters first ask the renderer to apply the value and then retain public state according to
the individual setter's success path. Scissor enable is a separate
\cnaclass{RasterizerState::ScissorTestEnable} value. A useful test therefore draws across the
boundary; property round trips alone are insufficient.

Three lifecycle rules define when CNA replaces custom rectangles:

\begin{itemize}
  \item Construction initializes the full logical viewport. Current resize handling also sets
        the scissor to full bounds after an actual logical or physical-viewport change.
  \item \texttt{Present()} preserves custom state while the renderer's logical size and physical
        default rectangle remain unchanged.
  \item Every 2D, cube, MRT, or backbuffer target switch resets both to the first destination's
        full bounds, even for a redundant binding.
\end{itemize}

Renderers may use a physical default viewport distinct from the logical public dimensions for
letterbox or overscan. Chapter~\ref{ch:renderer-contract},
\S\ref{sec:backend-viewport-scissor-matrix}, records draw-time coverage and exceptions.

\section{Clear, present, and reset}
\label{sec:clear-present-reset}

The four clear overloads have intentionally different scopes:

\begin{center}
\small
\begin{tabular}{@{}p{0.31\textwidth}p{0.60\textwidth}@{}}
\toprule
\textbf{Call} & \textbf{Shared request} \\
\midrule
\texttt{Clear(Color)} & target, depth, and stencil; depth uses current \texttt{Viewport.MaxDepth}, stencil uses zero \\
\texttt{Clear(options,color,depth,stencil)} & exact requested aspects after attachment masking \\
\texttt{Clear(r,g,b,a)} & CNAEXT direct color-hook call; it does not pass through full aspect routing \\
\texttt{Clear(Color,depth)} & CNAEXT target plus depth convenience form \\
\bottomrule
\end{tabular}
\end{center}

FNA's \texttt{Vector4}-color overload is absent. CNA also exposes only parameterless
\texttt{Present()}; FNA's source/destination-rectangle and override-window form has no CNA
counterpart. Present refuses while a user target is bound, calls the renderer, then refreshes
viewport/scissor only if the reported destination geometry changed.

\subsection{ClearOptions and attachment masking}
\label{sec:clearoptions}

\cnaclass{ClearOptions} is the bitwise combination of \texttt{Target}, \texttt{DepthBuffer}, and
\texttt{Stencil}. Shared code validates a requested depth value, independently asks whether the
active 2D/cube target or backbuffer has depth and stencil, masks only absent aspects, and selects
one of seven non-empty renderer methods. A depth/stencil-only clear on an attachment with neither
becomes a no-op, matching current FNA.

This independent aspect query is important for \texttt{Depth16}/\texttt{Depth24} versus
\texttt{Depth24Stencil8} and for families with a standalone stencil plane. Family-specific
ordering and remaining defects---notably EasyGL's color-hook/depth coupling and D3D9's additional
backbuffer-format gate---are in \S\ref{sec:backend-clear-matrix}.

\subsection{Reset order and rollback boundary}
\label{sec:graphicsdevice-reset-order}

All four reset overloads end in
\texttt{Reset(const PresentationParameters\&, GraphicsAdapter*)}. The order is public behavior:

\begin{enumerate}
  \item Raise \texttt{DeviceResetting}; handlers still see the old adapter and parameters.
  \item Clone the request, normalize the renderer's applied color/depth formats, store the
        adapter and logical size, and update touch dimensions.
  \item Apply window state and virtual resolution inside a rollback guard. A failure restores
        public presentation state, adapter, logical size, touch dimensions, and attempts to
        restore the former window state before rethrowing the original diagnostic.
  \item Apply/clamp MSAA and write the applied count back; forward swap interval and the
        presentation-format update hook.
  \item Refresh viewport/scissor and raise \texttt{DeviceReset}.
\end{enumerate}

The rollback guard ends before MSAA, interval, and format hooks. A later exception can therefore
leave earlier work applied and suppress \texttt{DeviceReset}. Successful completion establishes
the shared route, not that a compositor accepted fullscreen or an interval request. Applied
presentation values are stronger than the original request but still depend on each family's
truthful reporting; see \S\ref{sec:backend-presentation-format-matrix} and
\S\ref{sec:backend-swap-interval-matrix}.

FNA stores the new state before its resetting event and performs one FNA3D backbuffer reset, so
event observations and native transaction shape differ.

\subsection{GraphicsDeviceManager event and ownership model}

A game-attached \cnaclass{GraphicsDeviceManager} registers the manager and device-service
interfaces but does not own the game device. Initial \texttt{CreateDevice()} raises
\texttt{PreparingDeviceSettings}, resets the existing device, subscribes to later device reset
events, and then raises \texttt{DeviceCreated}. The initial settle-in reset is intentionally not
forwarded as a manager reset pair. Subsequent \texttt{ApplyChanges()} reaches device reset; the
manager forwards the device's events once.

Edits made in \texttt{PreparingDeviceSettings} apply to that candidate only and are not copied
back into preferred fields. The callback must retain a non-null adapter and must not re-enter
\texttt{ApplyChanges}. Listener exceptions propagate and can interrupt the staged operation.

The manager subscribes to \texttt{GameWindow::ClientSizeChanged} with a lambda capturing raw
\texttt{this}, discards the removal token, and removes only service registrations on disposal.
Destroying or replacing a manager while its game window remains live can therefore leave a
dangling resize callback. Normal member lifetime avoids a later resize during base destruction,
but that ordering is not a general ownership guarantee.

Manager disposal raises \texttt{DeviceDisposing} even though it does not delete a game-owned
device; \cnaclass{Game} uses that notification for \texttt{UnloadContent}. The disposed flag is
set after the \texttt{Disposed} event, so a re-entrant or throwing listener remains another
source-proven lifecycle hole.

\section{Render targets}
\label{sec:render-targets}

\texttt{SetRenderTarget(RenderTarget2D*)}, the cube-face overload, and
\texttt{SetRenderTargets(vector)} all normalize through the plural path. An empty list restores
the backbuffer. \texttt{GetRenderTargets()} returns a new vector; CNA still lacks FNA's
no-allocation extension.

\subsection{Binding contract}
\label{sec:graphicsdevice-target-binding-contract}

Each public binding becomes a descriptor naming a 2D target or cube face, dimensions, and the
renderer-applied sample count. The shared route enforces:

\begin{itemize}
  \item at most four bindings, with D3D9's \texttt{Reach} profile narrowed to one;
  \item non-null, non-disposed targets with a usable private renderer;
  \item valid cube faces and zero for unsupported 2D array slices;
  \item equal dimensions and applied sample counts;
  \item no duplicate subresource, while distinct faces of one cube remain legal.
\end{itemize}

Native binding must succeed before public bindings and viewport/scissor are committed. CNA has no
redundant-binding early return: rebinding the same target reaches the renderer, resets rectangles,
and clears a \texttt{DiscardContents} destination again. Preserve and Platform usage retain
content; discard requests a black clear of color and each reported depth/stencil aspect. The API
does not guarantee that discarded content later reads as black.

\label{sec:worked-rendertarget}

RenderTarget2D offscreen(dev, 128, 128);

\subsection{Multiple render targets}
\label{sec:worked-mrt}

The public call accepts up to four \cnaclass{RenderTargetBinding} entries. That shape does not
establish that one draw writes all attachments. WebGPU rejects MRT; Software's current route does
not provide a portable multi-output stock-effect contract; diagnostic renderers may record only
logical state. D3D12 can bind several RTVs while stock draws still target slot zero. Use
\texttt{MultipleRenderTargets} as an initial query, then require a successful bind and a shader
and pixel oracle that distinguish every output. Chapter~\ref{ch:renderer-contract},
\S\ref{sec:backend-rendertarget-usage-matrix}, owns the current qualifications.

\section{Vertex and index bindings}
\label{sec:vertex-index-binding}

The singular and plural vertex APIs now describe one coherent state. A singular bind validates
the nonnegative element offset, replaces the vector with slot zero, and null clears both. The
plural form accepts up to sixteen entries, retains legal null slots, and sets the singular pointer
to slot zero (or null for an empty list). \texttt{GetVertexBuffer()} and
\texttt{GetVertexBuffers()} therefore agree. This corrects the stale split-state account in an
earlier edition.

The \texttt{Indices} property, \texttt{SetIndexBuffer}/\texttt{GetIndexBuffer}, and method-call
\texttt{Indices()} spellings all use the same index pointer. This is surface redundancy, not
independent state.

\section{Draw calls}
\label{sec:draw-calls}

Buffer-backed calls are \texttt{DrawPrimitives}, \texttt{DrawIndexedPrimitives}, and
\texttt{DrawInstancedPrimitives}. Shared validation checks bound resources, applied effect,
topology-derived element ranges, and vertex/index bounds before native submission. Sampler state
is applied before each route.

FNA's generic user-primitive methods become CNA overload sets for raw packed bytes and the four
built-in vertex types: \cnaclass{VertexPositionColor},
\cnaclass{VertexPositionColorTexture}, \cnaclass{VertexPositionTexture}, and
\cnaclass{VertexPositionNormalTexture}. Indexed variants accept 16- and 32-bit indices. Raw
nonstandard layouts require an explicit \cnaclass{VertexDeclaration}. Typed public objects are
packed into the asserted stream ABI before upload; callers must not reinterpret their
polymorphic C\texttt{++} object representation as GPU bytes.

Reusable scratch vectors stage user draws. Their capacity persists, so the first large call may
allocate while subsequent calls of the same or smaller size do not. That is an implementation
warm-up cost, not a per-draw allocation promise.

\subsection{Instanced binding transport}
\label{sec:graphicsdevice-instancing}

Current CNA no longer forwards only one instance buffer. The same
\texttt{FillVertexStreamBindings()} helper serves ordinary and instanced draws and copies up to
sixteen slot-aligned descriptions into \cnaclass{GpuDrawParams}: renderer handle, declaration,
stride, element offset, instance frequency, and count. Instanced validation applies the caller's
base vertex only to per-vertex streams and computes each instance stream's required records as
$1+\lfloor(n-1)/f\rfloor$.

Families still differ in accepted layouts and native divisor support. The complete current
boundary is \S\ref{sec:drawex-instancing-matrix}; a compile-successful two-stream call is not a
portable arbitrary-effect claim.

\subsection{Effect matrices}
\label{sec:extract-matrices}

Every shared draw starts World/View/Projection at identity, then uses
\texttt{dynamic\_cast<const IEffectMatrices*>} on the applied effect. Stock effects,
\cnaclass{ShaderEffect}, and CNA's current PBR effect implement that interface. A custom effect
that deliberately omits it receives identity transforms instead of an exception; screen-space
clip coordinates are a legitimate use of that fallback.

The CNAEXT \texttt{PrimitiveVerts()} helper converts a primitive count into the required vertex
count and rejects unknown topology. It mirrors an internal FNA helper but is public in CNA.

\section{Backbuffer readback}
\label{sec:backbuffer-readback}

Three \texttt{GetBackBufferData} overloads write \cnaclass{Color}: whole backbuffer, caller
offset, or an optional rectangle. Unlike FNA's generic method, CNA exposes no other destination
element type. Current shared code derives whole-image dimensions from
\cnaclass{PresentationParameters}, validates a positive in-bounds rectangle, checks a minimum
\texttt{elementCount}, reads RGBA bytes, and constructs each \cnaclass{Color} so its vptr-bearing
C\texttt{++} layout is never treated as a byte array.

Two caller-safety gaps remain. \texttt{startIndex} is not checked for negativity, and the method
checks \texttt{elementCount >= pixelCount} rather than capacity after the start index. The
signed width-times-height calculation is also not explicitly overflow-checked. Validate the
complete destination span before calling.

The method name does not define one image across families. Active-target, physical-backbuffer,
synthetic, and refusal classes are listed in \S\ref{sec:backend-readback-matrix}. Pixel evidence
must state the family and coordinate space.

\section{Resources and disposal}
\label{sec:resource-lifetime}

\cnaclass{GraphicsDevice} keeps a non-owning vector of resource addresses. A base-resource
constructor registers \texttt{this} and raises \texttt{ResourceCreated} before the derived native
handle exists. Derived disposal releases its renderer handle; the base then raises
\texttt{ResourceDestroyed}, removes the address, and marks itself disposed. Destructor-driven
\texttt{Dispose(false)} suppresses the resource's own \texttt{Disposing} event but still raises
the device's destroyed event.

Device disposal moves and clears the registry, disposes each resource, raises device
\texttt{Disposing}, destroys renderer/window state, quits SDL video, and finally marks the device
disposed. Two limits follow from that order:

\begin{itemize}
  \item a still-bound \cnaclass{RenderTarget2D} can throw during resource disposal after the
        registry has already been cleared, preventing renderer teardown and making retry
        incomplete;
  \item a device \texttt{Disposing} listener can re-enter because \texttt{IsDisposed} remains
        false until after the event and native teardown.
\end{itemize}

Unbind targets before explicit device disposal and do not dispose the device recursively from an
event. Renderer-specific in-flight/deferred destruction rules remain in the family chapters.

\subsection{GraphicsResource and relocation}

\cnaclass{GraphicsResource} supplies device, disposed state, name, tag, event, and
\texttt{ToString}. Its copy/move operations do not repair the device's address registry.
\cnaclass{Texture2D} is copyable and shares its renderer handle; several other resources are
movable. A destination can therefore remain live but untracked after relocation. Keep live
resources address-stable and within device lifetime; Chapter~\ref{ch:renderer-contract},
\S\ref{sec:backend-resource-tracking}, gives the ownership consequences.

\section{Adapters and format queries}
\label{sec:adapter-displaymode}

\cnaclass{GraphicsAdapter} exposes current/supported display modes, description, display name,
monitor handle, default/widescreen flags, and identity fields. On Linux, vendor/device IDs are
best-effort values from \texttt{sysfs}; elsewhere they can be zero. Revision and subsystem ID
are always zero at the pin. \cnaclass{DisplayMode} holds width, height, format, and computed
aspect ratio. The three device exception types are thin \texttt{runtime\_error} subclasses.

\subsection{Adapter enumeration}
\label{sec:adapters-list}

\texttt{getAdaptersProperty()} lazily builds one adapter per SDL display and caches the owning
\texttt{unique\_ptr} vector. \texttt{AdaptersChanged()} destroys and rebuilds it; do not retain
adapter references across that call. \texttt{DefaultAdapter} is the current first entry, not a
separate GPU-selection service.

\subsection{Profile and format-query scope}
\label{sec:adapter-format-queries}

D3D9 is the only family whose \texttt{IsProfileSupported}, render-target format query, and
backbuffer format query consult its native device caps. It combines profile whitelists with
native format support and clamps samples per format. Other builds return true for either profile;
render-target queries use a shared format list and report zero samples, while backbuffer queries
select \texttt{Color} and zero samples. These methods therefore are not portable hardware probes.

\section{CNA extensions and diagnostics}
\label{sec:cnaext-helpers}
\label{sec:noxna-helpers}

The extension surface falls into four groups:

\begin{center}
\small
\begin{tabular}{@{}p{0.24\textwidth}p{0.30\textwidth}p{0.37\textwidth}@{}}
\toprule
\textbf{Purpose} & \textbf{Representative methods} & \textbf{Boundary} \\
\midrule
Resource instrumentation & create/destroy hooks, add/remove reference, tracked count & Public for framework plumbing and tests; events occur at base construction/disposal boundaries. \\
Renderer identity/capability & renderer type/name, \texttt{SupportsCapability}, maximum texture dimension, unsupported-3D policy & Identity is compile-time; capability is optimistic unless the family overrides; the texture limit is enforced by content/texture paths. \\
State and effect plumbing & depth/blend/write toggles, current effect, graphics-profile switch, stored presentation parameters & Primarily internal routes; not substitutes for XNA state objects or a general runtime profile change. \\
Debug/recovery & context-recovery policy, string marker, renderer reference, legacy MSAA recreation & Renderer-specific or test-oriented; direct renderer access is not portable. \\
\bottomrule
\end{tabular}
\end{center}

\texttt{SetContextRecoveryEnabled(false)} can discard future texture CPU shadows even when the
family hook is empty; re-enabling cannot rebuild them. \texttt{SetStringMarkerEXT} is a no-op on
most families and can throw on D3D9. \texttt{RecreateRendererForMultiSampleCount} destroys the
renderer without preserving resources, state, events, or rollback; its header rationale is stale
now that normal reset applies MSAA. Retain it only for its legacy pre-resource tests.

Some convenience aliases and overloads still lack the expected \texttt{CNAEXT} annotation. A
strict-surface build is valuable but is not a proof that every untagged declaration belongs to
XNA.

\section{Summary}

\cnaclass{GraphicsDevice} supplies a coherent public state machine, not one uniform native
implementation. The strongest portable assumptions are the shared validation and binding
rules. Presentation fidelity, advanced draw paths, target behavior, and readback still require
the selected family's evidence. Applied values and discriminating output are more informative
than stored requests or successful property round trips.
