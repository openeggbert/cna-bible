\chapter{The Media System}
\label{ch:media-system}

\cnans{Media} is no longer the shell-heavy namespace described by CNA's older README count.
At the pinned revision it contains file-backed songs and libraries, playlist parsing, queued
music playback, visualization data, picture libraries, and FFmpeg video on the platforms where
FFmpeg is enabled. This chapter states those behaviors by subsystem; it does not replace the
stale README count with another undated test total.

Audio and Media form an intentional static-library cycle. \cnaclass{FrameworkDispatcher} in
Audio advances \cnaclass{MediaPlayer}, while Media sends song playback to the audio mixer.
CMake repeats the archives to resolve that link cycle. Removing either edge would require
reassigning the shared dispatcher and playback responsibilities.

\section{Song contract}

\cnaclass{Song} can be constructed from a path or discovered by a
\cnaclass{MediaLibrary} scan. A directly constructed song has null, non-owning
\texttt{Album}, \texttt{Artist}, and \texttt{Genre} links; a scan supplies those links from
the library hierarchy. \texttt{IsRated} and the 0--10 \texttt{Rating} are derived from ID3v2
\texttt{POPM} or Vorbis \texttt{RATING} tags. A source rating of zero means ``unrated.''
\texttt{IsProtected} is always false because protected files are not indexed.

\texttt{Duration} and \texttt{PlayCount} are mutable. Playback replaces the duration with the
decoder-reported value, and \texttt{MediaPlayer::Stop()} resets play counts across the current
queue. \texttt{Handle} is a CNAEXT path/handle accessor. \texttt{Equals} compares handles;
\texttt{GetHashCode} hashes the resolved handle. The latter deliberately avoids FNA's
identity-hash inconsistency for two equal songs.

\begin{lstlisting}
std::unique_ptr<Song> intro(
    Song::FromUri("Intro Theme", "Content/Audio/intro.ogg"));
MediaPlayer::Play(intro.get());
// MediaPlayer clones the Song; the caller still owns intro.
\end{lstlisting}

The fragment assumes the Media header, \texttt{<memory>}, and the applicable namespaces.

\begin{historynote}{FNA is not the complete API oracle}
FNA's \cnaclass{Song} omits \texttt{Album}, \texttt{Artist}, \texttt{Genre}, and
\texttt{ToString()} from the XNA 4.0 surface. Repeated FNA-only reviews missed the difference;
comparison with the pinned \texttt{xna4-spec} data found it. Chapter~\ref{ch:xna4-spec-auditing}
explains why API parity with FNA and with XNA are separate claims.
\end{historynote}

\begin{limitationnote}{Advertised loose-file extensions}
The ContentManager song reader advertises \texttt{.aac} and \texttt{.wma}, but CNA's vendored
SDL3\_mixer has no decoder for either format. The MediaLibrary scanner omits them. A loose-file
resolution match therefore establishes that a \cnaclass{Song} can name the file, not that the
mixer can decode it. MP3, Ogg, WAV, FLAC, and Opus follow the installed decoder routes.
\end{limitationnote}

\section{MediaLibrary and metadata}
\label{sec:medialibrary}

\cnaclass{MediaLibrary} scans the host music and picture directories returned by
\texttt{SDL\_GetUserFolder}; a CNAEXT override makes tests independent of the CI account's
files. It builds \cnaclass{SongCollection}, \cnaclass{Album}, \cnaclass{Artist}, and
\cnaclass{Genre} relationships, plus the parallel picture hierarchy. \texttt{SavePicture()}
creates a ``Saved Pictures'' node on first use.

The in-tree metadata parser handles:

\begin{itemize}
  \item Ogg Vorbis comments and Ogg Opus \texttt{OpusTags};
  \item ID3v2.3/2.4 title, artist, album, genre, track, rating, and picture frames;
  \item Latin-1, UTF-16 with byte-order mark, UTF-16BE, and UTF-8 ID3 text;
  \item native FLAC \texttt{VORBIS\_COMMENT} and picture blocks;
  \item \texttt{.m3u} and \texttt{.m3u8} playlists as UTF-8.
\end{itemize}

Files without readable tags fall back to filename, parent directory, and grandparent directory
for title, album, and artist. Missing playlist entries are skipped. Album art comes from
\texttt{cover.jpg}/\texttt{folder.jpg} or embedded ID3/FLAC pictures; the front-cover picture
type wins when present.

The conversion from ID3's 0--255 rating and the various informal Vorbis rating scales to XNA's
0--10 property is CNA policy, not an XNA rule. Likewise, scans are synchronous snapshots;
there is no \texttt{MediaLibrary::Refresh()}.

\begin{historynote}{Testing values across layer boundaries}
The tag parser once read \texttt{TRCK} correctly while MediaLibrary discarded the value when
constructing \cnaclass{Song}. A fixture with several distinct track numbers exposed the drop;
a parser-only test could not. The current integration fixture checks the values after library
construction.
\end{historynote}

\section{Playback and queue ownership}

\cnaclass{MediaPlayer} supplies song and collection playback, pause, resume, stop, shuffle,
repeat, queue navigation, events, and visualization. \cnaclass{Playlist} is read-only, as on
XNA. \cnaclass{MediaQueue}\texttt{::Add(Song*)} adopts its pointer, whereas
\cnaclass{SongCollection} is non-owning. To keep the queue from deleting library-owned songs,
\texttt{MediaPlayer::Play} clones each input song and enqueues the clone.

In linear mode, next/previous clamp at the ends unless repeat is enabled. With repeat, the end
wraps to the beginning. Shuffle chooses uniformly from the full queue, so a track may repeat
immediately. Sound-enabled builds use SDL3\_mixer's stopped callback to advance. The no-sound
fallback compares elapsed time with a known, nonzero duration; a zero-duration song does not
auto-advance.

Volume and mute are independent state. Setting volume while muted retains the new value for the
next unmute; the mixer alone receives zero gain while muted. \texttt{MediaStateChanged} and
\texttt{ActiveSongChanged} are deferred until \cnaclass{FrameworkDispatcher}\texttt{::Update()}.
\cnaclass{Game} calls the dispatcher during its normal update loop, but a caller using the
static media API outside \cnaclass{Game} must pump it explicitly.

\section{Visualization}

\texttt{MediaPlayer::GetVisualizationData()} consumes samples captured by SDL3\_mixer's
post-mix callback. The callback writes to a single-producer/single-consumer ring buffer without
allocation, locking, or exceptions. Sample slots are \texttt{std::atomic<float>} with relaxed
ordering so audio-thread writes and game-thread reads are defined C++ behavior. A reader may
still observe samples spanning adjacent callback batches; the resulting one-frame visual
imprecision is accepted.

A 512-sample Hann-windowed radix-2 FFT produces XNA's 256 bins. CNA scales a full-amplitude sine
to approximately 1.0 in its bin; XNA did not document a normalization. Disabled or not-yet-fed
visualization returns zero-filled arrays. Tests cover failed installation and removal of the
mixer tap so the enabled flag does not claim a callback that is absent or cannot be removed.

\section{Video contract}

Where \texttt{CNA\_FFMPEG\_AVAILABLE} is enabled, \cnaclass{VideoPlayer} uses FFmpeg for
decoding, a CNA renderer texture for frames, and SDL3 audio streaming. \texttt{Play()} rejects
a declared width, height, or frame rate that disagrees with the decoded stream.
\cnaclass{VideoSoundtrackType} is metadata only in both CNA and FNA; it does not duck or mute
tracks.

The public methods check disposed state and throw \texttt{ObjectDisposedException} after
\texttt{Dispose()}. \texttt{Dispose()} itself is idempotent. This differs from FNA because the
C++ destructor also calls \texttt{Dispose()}; throwing during that destructor could terminate
the process.

\texttt{SetAudioTrackEXT} and \texttt{SetVideoTrackEXT} select streams independently. A live
audio switch reopens only the audio output; a live video switch recreates the frame texture if
dimensions change. The audio buffer is cleared even when no audio device or audio track is
active, preventing unbounded accumulation and stale samples on a later play. Tests use a
multi-track fixture to observe sample-rate change and verify that the unrelated video texture
is retained.

\begin{lstlisting}
VideoPlayer player;
player.Play(introVideo);
player.SetAudioTrackEXT(1); // switches audio without recreating video output
\end{lstlisting}

\section{Platform limitations}

The pinned CMake configuration disables FFmpeg on Windows (MinGW and MSVC), Android, and
Emscripten. Video translation units are excluded on those targets, so using
\cnaclass{Video}/\cnaclass{VideoPlayer} is a link-time failure, not a runtime
\texttt{NotSupportedException}. Linux and macOS are the intended FFmpeg-enabled routes when
the required development packages are available.

There is also a native-Windows guard mismatch. CMake's unavailable set includes \texttt{WIN32},
but two \texttt{ContentManager.cpp} preprocessor guards check Emscripten, Android, and MinGW;
one repeats \texttt{\_\_MINGW32\_\_} and neither checks \texttt{\_WIN32}. An MSVC build can
therefore retain \cnaclass{Video} dispatch references after the implementations were excluded.
This is an open pinned-revision build defect.

\section{Evidence status}

Source and focused tests establish parsing, hierarchy construction, queue ownership, event
timing, visualization state, disposal, and multi-track reconfiguration. FFmpeg fixture tests
exercise decoding on the configured host. Those results do not establish video availability on
the CMake-excluded targets, nor do extension lists establish decoder support. The platform gate
and Windows mismatch are source-proven; no Windows video execution is claimed.
