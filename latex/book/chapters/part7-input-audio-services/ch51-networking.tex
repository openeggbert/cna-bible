\chapter{Networking and Session Semantics}
\label{ch:networking}

CNA's \cnans{Microsoft::Xna::Framework::Net} surface combines one functional LAN route with
several compatibility lifecycles. \texttt{SystemLink} uses the vendored ENet transport;
\texttt{Local}, \texttt{LocalWithLeaderboards}, \texttt{PlayerMatch}, and \texttt{Ranked} do
not. Code that only observes session objects can miss that distinction, so this chapter starts
with it.

\section{Session types and ownership}

\begin{center}
\begin{tabularx}{\textwidth}{@{}lX@{}}
\toprule
\textbf{NetworkSessionType} & \textbf{Pinned-revision behavior} \\
\midrule
\texttt{SystemLink} & ENet host/join, LAN discovery, handshake, application-data relay,
disconnect handling, simulated latency/loss, and host migration \\
\texttt{Local} & Synthetic state and events; no transport or local data delivery \\
\texttt{LocalWithLeaderboards} & Same synthetic lifecycle plus Chapter~\ref{ch:gamerservices}'s
local persistence \\
\texttt{PlayerMatch}, \texttt{Ranked} & Stubs; no matchmaking service \\
\bottomrule
\end{tabularx}
\end{center}

\texttt{Create}, \texttt{Find}, \texttt{Join}, and \texttt{JoinInvited} return a
caller-owned \cnaclass{NetworkSession}\texttt{*}. \texttt{Dispose()} releases transport and
owned gamer resources, but it does not delete the session object. The caller must perform both
operations, normally through an owning smart pointer with explicit disposal where required.

The game loop must call \texttt{Update()} each frame. Initial \texttt{GamerJoined} events are
different: subscribing replays the handler synchronously for gamers already in
\texttt{AllGamers}. Later joins arrive through the update queue.

\begin{lstlisting}
std::unique_ptr<NetworkSession> session(NetworkSession::Create(
    NetworkSessionType::SystemLink, 1, 8));

session->GamerJoined.Add(
    [](System::Object*, const GamerJoinedEventArgs& args) {
        // Existing gamers replay now; later joins arrive from Update().
    });

// Once per game update:
session->Update();
\end{lstlisting}

\begin{limitationnote}{The \texttt{maxGamers} compatibility quirk}
The create path does not forward the caller's \texttt{maxGamers}. The constructed session
reports the literal 69, preserving the FNA/XNA behavior recorded in the implementation. A game
that needs an eight-player limit in the example above must enforce eight itself.
\end{limitationnote}

\section{SystemLink transport}

The internal \texttt{ENetBackend} uses a star topology. Clients send application data to the
host; the host relays it to the target. \cnaclass{NetworkGamer}\texttt{::Id} and
\texttt{IsHost} are consistent across machines, unlike FNA's fixed zero/true placeholders.
\texttt{RoundtripTime} reads ENet's peer measurement.

LAN discovery uses UDP port 61190, protocol version 1, and a 150-ms search window. A finder sends
broadcast and loopback queries, then deduplicates replies by connect port. The game session uses
an OS-assigned ENet port; Emscripten reserves 61191 but cannot perform raw UDP browser discovery.
\cnaclass{QualityOfService}'s network-backed construction reports discovery round-trip time;
bandwidth remains unmeasured.

The protocol opcodes are \texttt{ClientHello=0x01}, \texttt{ServerWelcome=0x02}, gamer
join/leave \texttt{0x03}/\texttt{0x04}, reserved host change \texttt{0x05}, state change
\texttt{0x06}, and application data \texttt{0x10}. There are two ENet channels and at most 31
peers. Up to 64 application sends may wait for handshake completion; the oldest is evicted on
the 65th. Disconnect, gamer removal, and migration purge affected queued sends. An internal
dropped-packet counter supports tests and diagnostics but is not part of
\cnaclass{NetworkSession}'s public API.

Discovery packets are version-checked. Property indices must be in $[0,256)$, one-byte list
counts reject values above 255, and completed peers that repeat a hello are disconnected.
Host-only broadcasts from a non-host peer are also rejected. These checks assume that an
untrusted client can reproduce the documented wire format.

\section{Host migration}

When \texttt{AllowHostMigration=false}, loss of the host ends the session. When it is true, all
survivors choose the lowest remaining wire ID from their shared roster. No election packet is
needed. The peer owning that ID promotes itself; the others rediscover its cached gamertag and
perform a normal hello/welcome reconnect. Discovery is retried for three 150-ms windows.

Migration clears remote gamers and wire-ID state first. Consequently, reconnecting peers see
leave and join events and receive new \cnaclass{NetworkGamer} objects; sockets and object
identity are not preserved. If the new host cannot be discovered, the session ends.

\texttt{SimulatedLatency} and \texttt{SimulatedPacketLoss} affect received application data.
They do not delay session-management packets or the host's relay hop. FNA stores these values
without applying them; CNA uses them as transport-test controls.

\section{Delivery guarantees}

ENet can express three behaviors for XNA's five \cnaclass{SendDataOptions} values:

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{XNA option} & \textbf{ENet flag} & \textbf{Observed guarantee} \\
\midrule
\texttt{None} & \texttt{UNSEQUENCED} & best effort, unordered \\
\texttt{InOrder} & none & best effort, sequenced \\
\texttt{Reliable} & \texttt{RELIABLE} & reliable and ordered \\
\texttt{ReliableInOrder} & \texttt{RELIABLE} & reliable and ordered \\
\texttt{Chat} & \texttt{RELIABLE} & reliable and ordered \\
\bottomrule
\end{tabular}
\end{center}

ENet's reliable channel is ordered, so CNA cannot reproduce ``reliable but unordered'' without
adding another protocol. \texttt{Reliable} therefore receives the stronger ordered guarantee.
\texttt{Chat} uses the same route by CNA policy.

\section{Compatibility limits and asymmetries}

Even in a \texttt{SystemLink} session, voice transport and invitations are absent.
\texttt{EnableSendVoice()} and \texttt{SendPartyInvites()} do nothing; voice and private-slot
properties retain false defaults. \texttt{NetworkMachine::RemoveFromSession()} throws
\texttt{NotImplementedException}. Invite and TrueSkill/arbitration events are never raised.
\texttt{JoinInvited()} creates a synthetic \texttt{PlayerMatch} lifecycle rather than joining
a service-backed session.

Two inherited data-shape problems are visible to applications:

\begin{itemize}
  \item \cnaclass{PacketWriter} writes \cnaclass{Color} as four bytes, while
        \cnaclass{PacketReader}\texttt{::ReadColor()} expects four floats. They are not inverses.
  \item \texttt{ReceiveData(PacketReader\&, NetworkGamer*\&)} fills and rewinds the reader but
        returns zero because its local length is never updated. Gate it with
        \texttt{IsDataAvailable}, or use the byte-vector overload for an accurate count.
\end{itemize}

\begin{lstlisting}
PacketWriter writer;
writer.Write(playerTintColor); // four bytes
localGamer->SendData(writer, SendDataOptions::Reliable);

std::vector<SharpRuntime::bytecs> rgba(4);
NetworkGamer* sender = nullptr;
while (localGamer->getIsDataAvailableProperty()) {
    int count = localGamer->ReceiveData(rgba, sender);
    if (count == 4) {
        Color tint(rgba[0], rgba[1], rgba[2], rgba[3]);
    }
}
\end{lstlisting}

The mutable \cnaclass{NetworkSessionProperties} indexer also grows the collection on an
out-of-range access because C++ cannot distinguish read and write through the translated
mutable reference. Use a \texttt{const} reference for bounds-checked reads.

\section{Asynchronous lifecycle constraint}

All session \texttt{Begin*}/\texttt{End*} pairs share one static
\texttt{NetworkSessionAction*}. Only one create, find, or join operation can be outstanding in
the process, even across different sessions. A second \texttt{Begin*} throws until the matching
\texttt{End*} deletes and clears the shared action. The operations are positioned to complete
synchronously because their work occurs in the matching \texttt{End*} path.

This design once depended on
\texttt{GamerServicesDispatcher::}\allowbreak\texttt{UpdateAsync()} returning false,
which it does not after initialization. The resulting busy loop and its isolated regression
harness are described in Section~\ref{sec:gamerservices-hang}.

\section{Lifetime hardening}

\begin{historynote}{Defects found under integration and sanitizers}
The network module has corrected the following distinct failures:

\begin{itemize}
  \item \texttt{Dispose()} could run twice, traverse gamer pointers freed by the first call,
        and trigger a sanitizer-detected use-after-free;
  \item one disposal left raw pointers visible through gamer collections and \texttt{Host};
  \item session-created gamer objects leaked because the session did not own their destruction;
  \item asynchronous callbacks were stored but not invoked, including reentrant replacement;
  \item \texttt{End*} cleared the shared action without deleting it;
  \item local IDs derived from collection size collided after remove/add;
  \item pre-handshake application data was dropped, then a first queue fix failed to purge
        entries when peers left;
  \item a disposed \texttt{GamerCollection} enumerator's \texttt{MoveNext()} dereferenced a null
        collection even though \texttt{Current} already guarded the same state.
\end{itemize}

The current \texttt{Dispose()} is idempotent, clears all gamer collections and \texttt{Host},
and releases owned gamer objects. Focused tests cover double disposal, post-disposal exposure,
action counts, callbacks, ID allocation, and queue eviction. AddressSanitizer was the observation
point for the original double-dispose failure; ordinary unit success alone had not exposed it.
\end{historynote}

\section{Evidence status}

Codec, hostile-input, policy, ownership, simulated loss/latency, and compatibility behaviors
have focused tests. An out-of-process, two-instance ENet harness establishes cross-process
SystemLink delivery on the recorded host. It does not establish Internet matchmaking, voice,
browser UDP discovery, or delivery on an untested platform. Host migration is runtime-observed
through the local discovery/reconnect route; it preserves neither sockets nor gamer-object
identity.
