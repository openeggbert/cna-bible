\chapter{Repository Map}
\label{ch:repo-map}

Volume~I's ecosystem chapter covered the six repositories this book treats as CNA's core
dependency and verification graph in depth. This appendix places them in the context of the
wider \texttt{openeggbert} GitHub organization, for a reader who wants to go further than this
book's own deliberately bounded scope.

\section{The six repositories this book covers in depth}

\begin{center}
\begin{tabular}{ll}
\toprule
\textbf{Repository} & \textbf{Role} \\
\midrule
\texttt{cna} & The core C\texttt{++}23 XNA~4.0 reimplementation this book is about \\
\texttt{sharp-runtime} & C\texttt{++} subset of the .NET base class library, CNA's foundation \\
\texttt{easy-gl} & Toolkit-independent OpenGL/OpenGLES wrapper, backs the EASYGL backend \\
\texttt{free-direct} & Narrow DirectDraw/DirectSound/DirectPlay reimplementation, backs DX3 \\
\texttt{xna4-spec} & Machine-readable XML spec of the real XNA~4.0 API, used for auditing \\
\texttt{cna-samples} & C\texttt{++} ports of the 86 official Microsoft XNA~4.0 samples \\
\texttt{cna-examples} & Original, MIT-licensed in-app demo catalog for CNA \\
\bottomrule
\end{tabular}
\end{center}

\section{Other CNA-adjacent repositories, out of this book's scope}

Several further repositories extend or sit alongside CNA without being covered in depth here,
since this book's scope was deliberately bounded to the repositories CNA's own build system
and documentation directly name as dependencies or verification partners:
\texttt{cna-template}, \texttt{cna-extended}, and \texttt{cna-craft} (further CNA-adjacent
projects), \texttt{meta-gl} (the lower-level typed OpenGL/GLES wrapper \texttt{easy-gl} itself
depends on, covered briefly in this volume's easy-gl chapter), and \texttt{easy-3d}.

\section{Real games and tools built on this stack}

\texttt{free-eggbert} and \texttt{planetblupi} are the two real legacy games --- \emph{Speedy
Blupi} and \emph{Planet Blupi} --- whose real call sites shaped \texttt{free-direct}'s own API
surface, covered as a worked case study in Chapter~18 of this volume.
\texttt{mobile-eggbert} (with a related \texttt{mobile-eggbert-legacy} and a libGDX variant)
appeared directly in Volume~I's WebGPU backend chapter, as the independent, real XNA-style
game whose unmodified run against that experimental backend was one of this book's strongest
pieces of evidence for a backend actually working. \texttt{mesh-craft} and
\texttt{galaxy-eggbert} are further games/tools built on this ecosystem, outside this book's
scope.

\section{A long tail of documentation and marketing sites}

The \texttt{openeggbert} organization also hosts a considerable number of
\texttt{*.openeggbert.com}-named repositories --- per-project documentation or marketing
sites (for instance \texttt{cna.openeggbert.com}, \texttt{easygl.openeggbert.com},
\texttt{sharpruntime.openeggbert.com}) --- which this book does not cover at all, since they
are presentation layers over the underlying code repositories rather than sources of new
technical fact.

\section{A note on repositories unrelated to CNA}

Several repositories in the same organization --- \texttt{speedyblupi.com},
\texttt{BlupiEdit}, \texttt{tiled-blupi}, and a handful of forked repositories --- relate to
the Blupi game franchise's own history independent of CNA/\texttt{free-direct}, or are forks
maintained for unrelated reasons. They are outside this book's scope entirely and are noted
here only so a reader browsing the organization's repository list is not left wondering
whether an omission was accidental.
